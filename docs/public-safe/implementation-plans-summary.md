## Public Review Criteria

A reviewer should be able to see that the project uses:

1. explicit scope and acceptance criteria;
2. separation between plan and execution evidence;
3. validation notes for implemented changes;
4. traceability from data architecture to API and dashboard outcomes;
5. honest distinction between completed, partial and pending work.

## Internal Detail Boundary

Detailed execution strategy, private prioritization and product reasoning are
kept out of this public layer. The summaries focus on engineering intent,
validation discipline and portfolio-readable outcomes.
